# resolve-short-one

DaVinci Resolveで開いている長尺の完成動画から、Shorts・X・TikTok向けの短編を**一本ずつ**企画・制作する、Codex用のSkillです。「reckの知識の森」の動画で紹介した制作手順を、個人の保存先や制作素材に依存しない形に整理して公開しています。

短く切り抜くだけでなく、初見の人に一つの答え・具体例・気づきを渡し、元動画の続きを見たくなる構成を重視します。

## できること

- 元動画を調べ、一本分の構成・全画面文言・レイアウトを提案する。
- ユーザーの構成承認後に、編集・書き出し・検証を進める。
- 元の横画面と字幕を活かした縦画面を作り、発話中に映像・音声をフェードして終える。
- 最終版MP4と、タイトル・説明文を各2案まとめた同名TXTを納品する。
- 完成品への評価を受けて同じ一本を修正し、依頼があれば共通の判断をSkillへ残す。

構成だけの相談にも使えます。次の一本は明示的に依頼してから進めます。

## 必要な環境

- DaVinci Resolveと、利用できる長尺の完成動画・素材。
- ローカルファイルと編集ツールを扱えるCodex環境。
- CodexからResolveを読み取り・操作するための接続。動画では **File → Setup AI Assistants** を入口にしています。実際の利用可否はResolveの版と環境で確認してください。
- 制作に必要な書き込み権限、書き出し・検証手段。補助ツールが必要になる場合は、実際の環境で確認します。

これはAIに渡す手順書です。MCPサーバーやResolveプラグイン、動画素材、Python・FFmpeg等の実行環境は同梱していません。Skillの導入だけではResolveへの接続設定は完了しません。

## 導入

### プロジェクト内に置く場合

作業するプロジェクトのルートで、次を実行します。同名のSkillがある場合は、その内容を確認してから更新してください。

```sh
git clone https://github.com/07KazumaAoyama29/resolve-short-one.git .agents/skills/resolve-short-one
```

Gitを使わない場合は、GitHubの **Code → Download ZIP** から展開し、フォルダー名を `resolve-short-one` にして `.agents/skills/` の下へ置きます。`SKILL.md` と `agents/`、`references/` の位置関係を保ってください。再配布時は `LICENSE` も残します。

```text
作業プロジェクト/
└── .agents/
    └── skills/
        └── resolve-short-one/
            ├── SKILL.md
            ├── agents/openai.yaml
            ├── references/tool-editing.md
            ├── references/explanation.md
            ├── README.md
            └── LICENSE
```

複数プロジェクトから使う場合は、利用環境が対応するユーザー共通のSkill保存先を使えます。公式案内では `~/.agents/skills` です。配置先や読み込みの仕様は[OpenAI公式のSkills説明](https://learn.chatgpt.com/docs/customization/overview#skills)を参照してください。

導入後、Codexで `$resolve-short-one` が選べるか確認します。表示されない場合は、新しいチャットまたは利用環境で必要な再読み込みを行ってください。

## 最初の一本を依頼する

Resolveで対象の完成版を開き、次のように依頼します。

```text
$resolve-short-one を使って、Resolveで開いている長尺完成版からShortを一本作りたい。
まず対象のプロジェクトと完成版を確認し、構成案を一つ提示してください。
実際の映像・音声を優先し、素材固有の具体例や気づきと、
本編で確かめたくなる続きを含めてください。
私が構成を承認してから制作してください。
納品先は今回の作業フォルダー内のShortsフォルダーにしてください。
```

構成と表示文言を確認し、よければその一本の制作を依頼します。完成後は動画を実際に再生し、音のつながり、文字の読みやすさ、意味が変わっていないかを確認してください。

## 動画で紹介した担当分担

| 担当 | 役割 |
| --- | --- |
| GPT-6 Astra | 構成案・最終レビュー |
| GPT-6.1 Sol / Extra High | 下調べ・承認後の制作・検証を担当するサブエージェント |
| ユーザー | 構成の承認・完成品の評価 |

Skillにはこの分担を残しています。モデル名・推論強度・サブエージェントの利用可否は環境で確認します。利用できない場合は、使えるモデルや単独担当での進行を明示的に指定してください。指定できなかった設定を、使用済みとして扱いません。

Resolveを操作する担当は同時に一人です。分担しても、必ず速く・安くなるという比較結果は示していません。

## 自分の用途に合わせて改善する

完成品に改善点があれば、「どこが」「なぜ」「どうなってほしいか」を伝え、まずその一本を修正します。今後にも使いたい判断なら、続けて次のように依頼できます。

```text
今直した判断基準を、次回にも使えるようにresolve-short-oneへ反映してください。
この動画だけの秒数や文言は共通ルールにせず、
既存の方針と矛盾しない形にしてください。
変更した箇所と、その理由を示してください。
```

Skillを書き換えたことと、次の別素材でも改善することは別です。次回の結果を見て調整してください。自分で改良したSkillを更新・再導入するときは、変更を失わないように差分を確認します。

## 長尺一本分を作り終えた後の整理

制作中の画像・中間動画・検証ファイルは、微調整や再編集に必要な場合があります。一本できるたびに消すのではなく、**同じ長尺から必要なShortをすべて作り終えた後**に整理します。

動画で紹介した整理は、Skillによる自動削除ではなく、完了後に別途依頼する運用です。次の入力例を使えます。

```text
この長尺動画からのShort制作はすべて完了しました。
制作ファイルを整理してください。

・各Shortの最終版MP4と、同名のタイトル・説明文TXTを残す。
・この長尺のShort制作に使った中間動画、一時素材、検証ログ、
  スクリプト、不要な旧版・バックアップを削除候補にする。
・元の長尺動画、本編プロジェクト、他の制作物、
  Skillが参照する資料は削除対象にしない。
・Resolveが参照している素材も確認し、
  削除すると再編集できなくなるものを明示する。

削除前に「残す完成ファイル」「削除するフォルダー」
「再編集への影響」を簡潔に提示し、私の承認を待ってください。
承認後に削除し、最終版MP4とTXTが残っていることを確認してください。
```

最終MP4/TXTだけでは、Resolveで同じ状態を再編集できるとは限りません。参照素材を残すかどうかは、具体的な影響を見て決めます。

## 公開版に含めているもの

- [SKILL.md](SKILL.md)：制作手順・判断基準。
- [agents/openai.yaml](agents/openai.yaml)：Codexの表示名と呼び出し例。
- [操作・ツールの文章例](references/tool-editing.md)と[解説の文章例](references/explanation.md)：判断理由を理解するための一般化した例。

元の個人用Skillに含まれる実動画、画面画像、会話ログ、素材パス、プロジェクト識別子、検証データは公開版に含めていません。そのため、動画で使った個人用Skillと参考資料の内容は異なります。参考作品の映像・テンポをそのまま再現するものではありません。

公開版の書式・参照リンクを確認していますが、あらゆる環境での制作成功や、再生数・視聴維持率を保証するものではありません。素材の文脈と最終動画は利用者自身でも確認してください。
